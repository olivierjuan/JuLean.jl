Contracts, Runtime Enforcement & Docstring Reflection

JuLean.@contract — Macro
@contract function ... end

Enforces contracts (@requires, @ensures) on a function at runtime.

source
JuLean.@formalize — Macro
@formalize function ... end
@formalize struct ... end
@formalize Module.func

Annotates a Julia function or struct definition with formal contracts:

  • For struct: extracts the LeanStructure, registers it in STRUCT_REGISTRY & CUSTOM_TYPE_REGISTRY.
  • For function: extracts FormalSpecification, instruments runtime contracts, and enables formal verification.
  • For function reference (Module.func or func): automatically extracts contracts from the function's Markdown docstrings!

Formalizes a function directly by extracting its implementation and docstring contracts, and registers it in SPEC_REGISTRY and INLINE_REGISTRY.

contracted(func::Function, argtypes::Tuple=()) -> Function

Wraps an existing Julia function and returns a new function that dynamically checks preconditions (@requires) and postconditions (@ensures) parsed from func's Markdown docstring whenever JuLean.CONTRACTS_ENABLED[] is true.

JuLean.@requires — Macro
@requires condition [message]

Declare a function precondition.

Can be used in two complementary ways:

  1. Inside Markdown docstrings (recommended for zero-dependency libraries): Annotate standard Julia docstrings with -@requires <condition>`. JuLean extracts these non-invasively via docstring reflection (JuLean.formalize!(func)`), allowing client libraries to declare formal contracts without taking a dependency on JuLean.
  2. Inside function bodies: Placed directly in functions annotated with @contract or @formalize (or used standalone for runtime precondition checking).

Throws ContractViolationError if condition evaluates to false when contracts are enabled.

source
JuLean.@ensures — Macro
@ensures condition [message]

Declare a function postcondition.

Can be used in two complementary ways:

  1. Inside Markdown docstrings (recommended for zero-dependency libraries): Annotate standard Julia docstrings with -@ensures <condition>`. Inside postconditions,resultrefers to the return value of the function. Extracted non-invasively by JuLean's reflection engine (JuLean.formalize!(func)`).
  2. Inside function bodies: Placed directly in functions annotated with @contract or @formalize. Inside postconditions, result refers to the return value of the function.

Throws ContractViolationError if condition evaluates to false upon function return.

source
JuLean.@invariant — Macro
@invariant condition [message]

Declare a loop or state invariant.

Can be used in two complementary ways:

  1. Inside Markdown docstrings: Annotate standard Julia docstrings with -@invariant <condition>`` for non-invasive contract specification extracted during reflection.
  2. Inside loop bodies: Placed directly inside while or for loops in functions annotated with @contract or @formalize. Enforced on every iteration at runtime, and verified symbolically via Bounded Model Checking (JuLean.verify(fn; backend=:BMC)).

Throws ContractViolationError if condition evaluates to false during loop execution.

JuLean.@forall — Macro
@forall(var in collection, condition)
@forall(var::Type, condition)

Universal quantifier specification.

  • For discrete collections or ranges (e.g. i in 1:n), evaluates all(i -> condition, collection) at runtime.
  • For typed domains (e.g. x::Real), evaluated symbolically by Lean 4 and SMT solvers.

JuLean.INLINE_REGISTRY — Constant
INLINE_REGISTRY

Global registry mapping function identifiers (Symbol or Expr) to inlining templates (args::Vector{Symbol}, body::Expr). Functions registered here are transparently inlined by JuLean's SMT and Lean 4 engines whenever called within @formalize specifications.

source
JuLean.register_runtime_only! — Function
register_runtime_only!(f::Function) -> f
register_runtime_only!(name::Symbol) -> name

Registers f (or name) as a runtime-only helper. Any statement of a formalized function body that contains a call to a runtime-only name is dropped from the transpiled body — whole-statement, never partially rewritten. Typical use: a solver package keeps debug contract checks inside its kernels behind a predicate such as if _contracts_enabled() ... end and registers the predicate (and the check helpers) here.

source
JuLean.strip_runtime_only — Function
strip_runtime_only(ex) -> Expr

Removes every statement containing a call to a register_runtime_only!-ed name, recursively through nested blocks (if / for / let bodies). Returns ex unchanged when nothing matches.

source
JuLean.RUNTIME_ONLY_REGISTRY — Constant
RUNTIME_ONLY_REGISTRY

Global registry of function names (Symbol) whose call sites are runtime-only instrumentation: debug contract checks, assertions, or logging attached to the running implementation. Statements in @formalized bodies that call a runtime-only function are stripped before SMT / Lean 4 transpilation (see strip_runtime_only), so such instrumentation can live inside the real kernel without breaking the formal pipeline.

JuLean.verify_with_z3 — Function
verify_with_z3(spec::FormalSpecification; logic::String="", timeout::Float64=30.0) -> VerificationResult

Verifies a specification using Z3.

  • unsat: The specification holds for all inputs satisfying preconditions -> StatusVerified.
  • sat: A counterexample violating postconditions was found -> StatusCounterexample.
  • unknown: SMT solver was inconclusive -> StatusUnverified.

Soundness: specifications without postconditions (vacuous falsification target) and specifications with imperative loops (dropped by the SMT translation) are rejected as StatusUnverified rather than reported as verified.

source
JuLean.verify_bmc — Function
verify_bmc(spec::FormalSpecification; depth::Int=3, logic::String="ALL", timeout::Float64=30.0) -> VerificationResult

Performs Bounded Model Checking (BMC) by unrolling loop iterations in SMT. The falsification target is not (invariants ∧ postconditions) at the final unrolled state; unsat means the loop kernel satisfies its specification for every execution of exactly depth iterations.

source

Generates a complete SMT-LIB 2.6 query file asserting the preconditions and the NEGATION of the postconditions. If satisfiable (sat), a counterexample exists. If unsatisfiable (unsat), extracts the minimal unsat core of preconditions.
