API Reference

Contracts & Design-by-Contract

JuLean.@contract — Macro
@contract function ... end

Enforces contracts (@requires, @ensures) on a function at runtime.

source
JuLean.@formalize — Macro
@formalize function ... end
@formalize struct ... end
@formalize Module.func

Annotates a Julia function or struct definition with formal contracts:

  • For struct: extracts the LeanStructure, registers it in STRUCT_REGISTRY & CUSTOM_TYPE_REGISTRY.
  • For function: extracts FormalSpecification, instruments runtime contracts, and enables formal verification.
  • For function reference (Module.func or func): automatically extracts contracts from the function's Markdown docstrings!
source
JuLean.@requires — Macro
@requires condition [message]

Declare a function precondition. Can be used inside @contract or @formalize functions, or standalone as a runtime precondition check.

source
JuLean.@ensures — Macro
@ensures condition [message]

Declare a function postcondition. Can be used inside @contract or @formalize functions. Inside postconditions, result refers to the return value of the function.

source
JuLean.@invariant — Macro
@invariant condition [message]

Declare a loop or data invariant.

source
JuLean.@forall — Macro
@forall(var in collection, condition)
@forall(var::Type, condition)

Universal quantifier specification.

  • For discrete collections or ranges (e.g. i in 1:n), evaluates all(i -> condition, collection) at runtime.
  • For typed domains (e.g. x::Real), evaluated symbolically by Lean 4 and SMT solvers.
source
JuLean.@exists — Macro
@exists(var in collection, condition)
@exists(var::Type, condition)

Existential quantifier specification.

  • For discrete collections or ranges (e.g. i in 1:n), evaluates any(i -> condition, collection) at runtime.
  • For typed domains (e.g. x::Real), evaluated symbolically by Lean 4 and SMT solvers.
source

p ⟹ q -> Bool

Logical implication operator: p ==> q is true unless p is true and q is false.

JuLean.verify_with_z3 — Function
verify_with_z3(spec::FormalSpecification; logic::String="", timeout::Float64=30.0) -> VerificationResult

Verifies a specification using Z3.

  • unsat: The specification holds for all inputs satisfying preconditions -> StatusVerified.
  • sat: A counterexample violating postconditions was found -> StatusCounterexample.
  • unknown: SMT solver was inconclusive -> StatusUnverified.

Soundness: specifications without postconditions (vacuous falsification target) and specifications with imperative loops (dropped by the SMT translation) are rejected as StatusUnverified rather than reported as verified.

source

SPEC_REGISTRY

Global registry mapping function names (Symbol) to their extracted FormalSpecification. Every function annotated with @formalize registers its specification here, making it available to verify, export_lean_file, and verification_summary.

transpile_to_lean_decl(spec::FormalSpecification; tactic="") -> (LeanDef, Union{LeanTheorem, Nothing})

Generates the Lean 4 def and, when postconditions are declared, the verification theorem. A specification without postconditions has nothing to prove, so no theorem is emitted (nothing is returned in its place).

source
JuLean.synthesize_tactic — Function
synthesize_tactic(spec::FormalSpecification) -> String

Generates an automated, intelligent Lean 4 tactic script matching the specification shape:

  • If quantifiers are present: introduces variables (intros).
  • If branching (if / elseif) is present: splits conditionals (split_ifs) and solves branches.
  • Solves goals via linarith, omega, decide, or rfl.

SMT & Bounded Model Checking

JuLean.generate_smtlib_query — Function
generate_smtlib_query(spec::FormalSpecification; logic="", produce_unsat_core::Bool=true) -> String

Generates a complete SMT-LIB 2.6 query file asserting the preconditions and the NEGATION of the postconditions. If satisfiable (sat), a counterexample exists. If unsatisfiable (unsat), extracts the minimal unsat core of preconditions.
